# Architecture Decision Records

Use ADRs for durable decisions with future consequences, especially:

- authority/governance boundaries;
- security/trust boundaries;
- component/process isolation;
- major technology commitments;
- deployment/recovery architecture;
- irreversible data/compatibility policy.

Do not create ADRs for routine implementation choices.

When a decision changes, add/supersede the ADR rather than silently rewriting historical reasoning.
